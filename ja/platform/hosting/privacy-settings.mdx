このページでは、組織管理者とチーム管理者が W&amp;B でプライバシー設定を構成して、チームの可視性、project へのアクセス、招待、report の共有、デフォルトのコードの保存を制御する方法について説明します。これらの設定を使用すると、組織全体でプライバシー設定を標準化したり、単一のチーム向けに制御を調整したりできます。

組織管理者は組織スコープでプライバシー設定を構成でき、チーム管理者はチームスコープで構成できます。組織スコープで構成した場合、その設定はその組織内のすべてのチームに適用されます。

<Note>
  チームのワークフローに予期しない変更が生じるのを避けるため、W&amp;B は、組織管理者がプライバシー設定を適用する前に、その組織内のすべてのチーム管理者と Users に事前に周知することを推奨します。
</Note>

<div id="enforce-privacy-settings-for-all-teams">
  ## すべてのチームにプライバシー設定を適用する
</div>

組織管理者は、組織設定の **Privacy** タブから、組織内のすべてのチームにプライバシー設定を適用できます。適用された設定は組織内のすべてのチームに反映され、チーム管理者はチームスコープでそれを上書きできません。適用中の設定をチーム管理者が開くと、W&amp;B は次のメッセージを表示します: 「This setting is locked because it&#39;s enforced org-wide. To make changes, please contact your org admin.」

組織のプライバシー設定を開くには、次の手順に従います。

1. 組織管理者としてサインインします。
2. Multi-tenant Cloud では、`https://wandb.ai/account-settings/[ORGANIZATION]/settings` にアクセスします。`[ORGANIZATION]` はご自身の組織名に置き換えてください。専用クラウドまたはセルフマネージドのデプロイでは、インスタンスの組織ダッシュボードを開きます。環境固有のURLについては、[Add and manage users](/ja/platform/hosting/iam/access-management/manage-organization#add-and-manage-users)を参照してください。
3. 左側のナビゲーションで **Privacy** を選択します。

以下のセクションでは、**Privacy** タブの設定について説明します。各設定はトグルで、W&amp;B は変更を即座に保存します。

<div id="access-control">
  ### アクセス制御
</div>

チームの可視性とメンバーの参加プロセスを管理します。

* **チームの可視性制限を強制する**: 各ユーザーは、自分が所属するチームとチームメンバーのプロフィールのみを表示できます。所属していないチームやユーザーは非表示になります。
* **チームへの自動参加を防止する**: 組織のメールドメインが一致するユーザーでも、どのチームにも自動的に参加できません。明示的な招待が必要です。
* **招待権限を制限する**: どのチームでも、新しいメンバーを招待できるのは管理者のみです。
* **招待をクレーム済みドメインに制限する**: 組織がクレーム済みのメールドメインで終わるメールアドレスを持つユーザーのみを、組織に招待できます。
  <Note>この設定は、メールドメインをクレーム済みの Enterprise 組織の場合に限り、[Multi-tenant Cloud](./hosting-options/multi_tenant_cloud) でのみ表示されます。[Domain capture](./iam/access-management/manage-organization#domain-capture) を参照してください。</Note>
* **APIキーの作成を無効にする**: ユーザーおよびチームのサービスアカウントは、新しいAPIキーを作成できなくなります。組織のサービスアカウントは引き続きキーを作成でき、既存のキーもそのまま機能します。[APIキーの作成を無効にする](./iam/api-keys#disable-api-key-creation) を参照してください。
  <Note>この設定は、専用クラウドおよびセルフマネージド v0.84.0 以降でのみ表示されます。</Note>

<div id="project-and-content-security">
  ### 非公開 project とコンテンツのセキュリティ
</div>

project のプライバシーを制御し、コンテンツの共有を管理します。

* **プライベート project を強制する**: すべてのチームの新規 project がプライベートまたは [restricted](./iam/access-management/restricted-projects) に設定され、チームスコープでは公開 (public) や open に変更できなくなります。
* **report の公開共有を無効にする**: 非公開 project の report の公開共有をオフにし、既存の公開リンクを無効化します。
* **デフォルトのコードの保存を無効にする**: すべてのチームで、デフォルトのコードの保存をオフにします。[コードの保存](/ja/models/app/features/panels/code) を参照してください。

<div id="smart-features">
  ### Smart features
</div>

**Smart features** セクションでは、LLM を活用した機能とデータ共有を制御します。このセクションは、組織が W&amp;B AI 機能へのアクセス権を持つ場合にのみ **Privacy** タブに表示されます。[ガバナンスとセキュリティ](/ja/aria/governance)を参照してください。

<div id="aria">
  ### ARIA
</div>

**ARIA** セクションでは、組織の projects 全体で ARIA が実行できる操作を制御します。このセクションは、組織で project memory が有効になっている場合にのみ **Privacy** タブに表示されます。

* **Enable project memory**: 規約や過去の修正内容といった project の詳細を ARIA が記憶し、以降の会話で活用できるようにします。ARIA は project のメモリを、その project を所有するチームと共有します。この設定がオフの場合、ARIA はメモリを使用せず、新たな記録も行いませんが、既存のメモリは保持されます。詳細は [project メモリの表示と管理](/ja/aria/overview#view-and-manage-project-memories) を参照してください。

<div id="configure-privacy-settings-for-a-team">
  ## チームのプライバシー設定を行う
</div>

組織スコープで設定が強制されていない場合、チーム管理者はチームの **Settings** ページの **Privacy** セクションで、自分のチームの設定を管理できます。

チームのプライバシー設定を開くには、次の手順を実行します。

1. `https://wandb.ai/[TEAM]` にアクセスします。`[TEAM]` はご自身のチーム名に置き換えてください。
2. 左側のナビゲーションで **Team settings** を選択します。
3. **Privacy** セクションを開きます。

**Privacy** セクションには次の設定が含まれます。変更内容は W&amp;B によって即座に保存されます。

* **Default visibility for new projects in [TEAM]**: チーム内の新しい project に W&amp;B が適用する可視性スコープを設定します。[Visibility scopes](./iam/access-management/restricted-projects#visibility-scopes) を参照してください。
* **Hide this team from all non-members**: メンバー以外のユーザーからチームを非表示にします。
  <Warning>チームを非表示にすると、そのチームに属するすべての公開 project および report への一般公開アクセスもブロックされます。この設定を適用する前に、W&amp;B が確認を求めます。</Warning>
* **Make all future team projects private (public sharing not allowed)**: チーム内で今後作成されるすべての project を非公開にします。
* **Allow any team member to invite other members (not just admins)**: 管理者だけでなく、すべてのチームメンバーが新しいメンバーを招待できるようにします。
* **Disable public sharing to outside of team for reports in private projects**: チームの非公開 project 内の report の公開共有を無効にします。既存のマジックリンクも無効化されます。
* **Automatically recommend new users with matching email domains (`[DOMAIN]`) join this team upon signup**: メールアドレスが組織で取得済みの email domain と一致する新規ユーザーに対し、サインアップ時にこのチームへの参加を促します。W&amp;B App では、`[DOMAIN]` には組織が取得済みの email domain が表示されます。
  <Note>この設定は [Multi-tenant Cloud](./hosting-options/multi_tenant_cloud) でのみ表示され、変更できるのは組織管理者のみです。組織が email domain を取得していない場合は、この設定の代わりに組織設定の **Enable domain capture** へのリンクが表示されます。[Domain capture](./iam/access-management/manage-organization#domain-capture) を参照してください。</Note>
* **Enable code saving by default**: チーム内のすべての run のコードを自動的に保存します。[Code saving](/ja/models/app/features/panels/code) を参照してください。

ここで設定した内容はこのチームにのみ適用され、組織内の他のチームには影響しません。
