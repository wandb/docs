---
title: "Why does deleting many artifacts at once time out?"
keywords: ["Artifacts", "Storage", "API"]
---

Deleting an artifact that contains many files from the W&B App can time out and return a `context deadline exceeded` error. Deleting a single small file succeeds, but deleting hundreds of artifacts or files at once fails. W&B support has identified this as a known issue with deleting artifacts that contain many files from the UI.

To work around it, delete artifacts programmatically in smaller batches with the [W&B Public API](/models/ref/python/public-api/api).

## Delete artifacts in batches

The following script steps through a project's artifact types and deletes each version, skipping the artifact types that W&B generates for you. Keep `DRY_RUN = True` for the first pass to review what the script deletes before you commit to it.

Replace the `<entity>` and `<project>` placeholders with your own values. Use your team or username for `<entity>`, not your organization name. Passing an organization name fails with `ValueError: Unable to parse 'ArtifactTypes' response data`.

<Warning>
Artifact deletion is irreversible. Because the script passes `delete_aliases=True`, it also deletes artifact versions that carry an alias such as `latest`. Review the dry-run output before you set `DRY_RUN` to `False`.
</Warning>

```python
import wandb

# Assumes you've run `wandb login` already.
entity = "<entity>"  # your username or team
project = "<project>"
project_path = f"{entity}/{project}"

# Set to False to actually delete. Deletion is irreversible.
DRY_RUN = True

# Delete only your own artifacts; skip W&B system-generated ones.
SKIP_TYPES = {"run_table", "code", "job"}

api = wandb.Api()

for art_type in api.artifact_types(project_path):
    if art_type.name.startswith("wandb-") or art_type.name in SKIP_TYPES:
        continue
    for collection in api.artifact_collections(project_path, art_type.name):
        for version in collection.artifacts():
            if DRY_RUN:
                print(f"[dry-run] would delete {version.name}")
            else:
                print(f"Deleting {version.name}")
                version.delete(delete_aliases=True)
```

To narrow the deletion further, filter on `art_type.name` or `collection.name` so the script processes one artifact type or collection at a time.

To remove an entire collection and every version in it, call [ArtifactCollection.delete()](/models/ref/python/public-api/artifactcollection#delete) on the collection instead of deleting versions one at a time.

The script reaches linked artifacts as well as source artifacts. Calling `delete()` on a linked artifact removes only the link and leaves the source artifact and its files in place, so those versions don't free any storage. To confirm that a collection holds source artifacts, check [ArtifactCollection.is_sequence()](/models/ref/python/public-api/artifactcollection).

To delete individual artifact versions interactively instead, use the **Manage storage** page described in [Manage storage](/platform/app/settings-page/storage).

## Reclaim the space

Deleted artifacts are soft-deleted first, then removed during garbage collection, so your storage meter doesn't drop immediately. For the timing and how to verify your usage, see [Why does the storage meter not update after deleting runs?](/support/models/articles/why-does-the-storage-meter-not-update-af) and [Delete an artifact](/models/artifacts/delete-artifacts).
