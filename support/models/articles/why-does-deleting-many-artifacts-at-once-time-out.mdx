---
title: "Why does deleting many artifacts at once time out?"
keywords: ["Artifacts", "Storage", "API"]
---

Deleting many artifacts or files in a single action from the W&B App can time out and return a `context deadline exceeded` error, even when deleting one small file succeeds. The UI also limits how many versions you can select at a time, which makes clearing a large project impractical.

To delete at scale, use the [W&B Public API](/models/ref/python/public-api/api) instead. Each version is deleted in its own request, so no single request has to cover the whole set.

In both scripts that follow, replace the `<entity>` and `<project>` placeholders with your own values. Use your team or username for `<entity>`, not your organization name. Passing an organization name fails with `ValueError: Unable to parse 'ArtifactTypes' response data`.

<Warning>
Artifact deletion is irreversible. Both scripts pass `delete_aliases=True`, so they also delete versions that carry an alias such as `latest`. Keep `DRY_RUN = True` and review the output before you set it to `False`.
</Warning>

## Delete one artifact type

Deleting a single type, such as `model`, is the narrowest option and the one to reach for first:

```python
import wandb

# Assumes you've run `wandb login` already.
entity = "<entity>"  # your username or team
project = "<project>"
artifact_type = "model"

# Set to False to actually delete. Deletion is irreversible.
DRY_RUN = True

api = wandb.Api()

for collection in api.artifact_collections(f"{entity}/{project}", artifact_type):
    for version in collection.artifacts():
        if DRY_RUN:
            print(f"[dry-run] would delete {version.name}")
        else:
            print(f"Deleting {version.name}")
            version.delete(delete_aliases=True)
```

To remove a collection and every version in it at once, call [ArtifactCollection.delete()](/models/ref/python/public-api/artifactcollection#delete) on the collection instead of iterating its versions.

## Delete every artifact in a project

The following script deletes **every** artifact version in the project, apart from the types W&B generates for you. Use it only when you intend to clear the whole project:

```python
import wandb

# Assumes you've run `wandb login` already.
entity = "<entity>"  # your username or team
project = "<project>"
project_path = f"{entity}/{project}"

# Set to False to actually delete. Deletion is irreversible.
DRY_RUN = True

# Delete only your own artifacts; skip W&B system-generated ones.
SKIP_TYPES = {"run_table", "code", "job"}

api = wandb.Api()

for art_type in api.artifact_types(project_path):
    if art_type.name.startswith("wandb-") or art_type.name in SKIP_TYPES:
        continue
    for collection in api.artifact_collections(project_path, art_type.name):
        for version in collection.artifacts():
            if DRY_RUN:
                print(f"[dry-run] would delete {version.name}")
            else:
                print(f"Deleting {version.name}")
                version.delete(delete_aliases=True)
```

Both scripts reach linked artifacts as well as source artifacts. Calling `delete()` on a linked artifact removes only the link and leaves the source artifact and its files in place, so those versions don't free any storage. To confirm that a collection holds source artifacts, check [ArtifactCollection.is_sequence()](/models/ref/python/public-api/artifactcollection).

<Note>
These scripts address bulk deletion, where one request covering many versions times out. If deleting a **single** artifact fails on its own, splitting the work doesn't apply. [Contact support](mailto:support@wandb.com) with the artifact path and the error.
</Note>

## Reclaim the space

Deleted artifacts are soft-deleted first, then removed during garbage collection, so your storage meter doesn't drop immediately. For the timing and how to verify your usage, see [Why does the storage meter not update after deleting runs?](/support/models/articles/why-does-the-storage-meter-not-update-af) and [Delete an artifact](/models/artifacts/delete-artifacts).
