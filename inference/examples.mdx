Use Serverless Inference with W&B Weave to trace model calls, evaluate performance, and compare models. You can also connect coding agents and chat backends to models hosted on Serverless Inference.

The following sections cover tracing, evaluation, coding agents, and chat backends. Before running an example, complete the [prerequisites](/inference/prerequisites/).

## Basic example: trace Llama 3.1 8B with Weave

This example shows how to send a prompt to the Llama 3.1 8B model and trace the call with Weave. Tracing captures the full input and output of the LLM call, monitors performance, and lets you analyze results in the Weave UI.

<Tip>
Learn more about [tracing in Weave](/weave/guides/tracking/tracing).
</Tip>

In this example:
- You define a `@weave.op()`-decorated function that makes a chat completion request.
- Weave records your traces and links them to your W&B entity and project.
- Weave automatically traces the function, logging inputs, outputs, latency, and metadata.
- The result prints in the terminal, and the trace appears in your **Traces** tab at [https://wandb.ai](https://wandb.ai).

```python
import weave
import openai

# Set the Weave team and project for tracing
weave.init("[YOUR-TEAM]/[YOUR-PROJECT]")

client = openai.OpenAI(
    base_url='https://api.inference.wandb.ai/v1',

    # Create an API key at https://wandb.ai/settings
    api_key="[YOUR-API-KEY]",

    # Optional: Team and project for usage tracking
    project="wandb/inference-demo",
)

# Trace the model call in Weave
@weave.op()
def run_chat():
    response = client.chat.completions.create(
        model="meta-llama/Llama-3.1-8B-Instruct",
        messages=[
            {"role": "system", "content": "You are a helpful assistant."},
            {"role": "user", "content": "Tell me a joke."}
        ],
    )
    return response.choices[0].message.content

# Run and log the traced call
output = run_chat()
print(output)
```

After running the code, view the trace in Weave using one of the following methods:
- Click the link printed in the terminal. For example, `https://wandb.ai/[YOUR-TEAM]/[YOUR-PROJECT]/r/call/01977f8f-839d-7dda-b0c2-27292ef0e04g`.
- Navigate to [https://wandb.ai](https://wandb.ai) and select the **Traces** tab.

With the basic trace working, you can move on to a richer workflow that goes beyond inspecting individual calls.

## Advanced example: use Weave evaluations and leaderboards

Besides tracing model calls, you can evaluate performance and publish leaderboards. This example compares two models on a question-answer dataset to show how Llama 3.1 8B and DeepSeek V3.1 perform against the same prompts.

```python
import os
import asyncio
import openai
import weave
from weave.flow import leaderboard
from weave.trace.ref_util import get_ref

# Set the Weave team and project for tracing
weave.init("[YOUR-TEAM]/[YOUR-PROJECT]")

dataset = [
    {"input": "What is 2 + 2?", "target": "4"},
    {"input": "Name a primary color.", "target": "red"},
]

@weave.op
def exact_match(target: str, output: str) -> float:
    return float(target.strip().lower() == output.strip().lower())

class WBInferenceModel(weave.Model):
    model: str

    @weave.op
    def predict(self, prompt: str) -> str:
        client = openai.OpenAI(
            base_url="https://api.inference.wandb.ai/v1",
            # Create an API key at https://wandb.ai/settings
            api_key="[YOUR-API-KEY]",
            # Optional: Team and project for usage tracking
            project="[YOUR-TEAM]/[YOUR-PROJECT]",
        )
        resp = client.chat.completions.create(
            model=self.model,
            messages=[{"role": "user", "content": prompt}],
        )
        return resp.choices[0].message.content

llama = WBInferenceModel(model="meta-llama/Llama-3.1-8B-Instruct")
deepseek = WBInferenceModel(model="deepseek-ai/DeepSeek-V3.1")

def preprocess_model_input(example):
    return {"prompt": example["input"]}

evaluation = weave.Evaluation(
    name="QA",
    dataset=dataset,
    scorers=[exact_match],
    preprocess_model_input=preprocess_model_input,
)

async def run_eval():
    await evaluation.evaluate(llama)
    await evaluation.evaluate(deepseek)

asyncio.run(run_eval())

spec = leaderboard.Leaderboard(
    name="Inference Leaderboard",
    description="Compare models on a QA dataset",
    columns=[
        leaderboard.LeaderboardColumn(
            evaluation_object_ref=get_ref(evaluation).uri(),
            scorer_name="exact_match",
            summary_metric_path="mean",
        )
    ],
)

weave.publish(spec)
```

After running this code, navigate to your W&B account at [https://wandb.ai/](https://wandb.ai/) and do the following:

- Select the **Traces** tab to [view your traces](/weave/guides/tracking/tracing).
- Select the **Evals** tab to [view your model evaluations](/weave/guides/core-types/evaluations).
- Select the **Leaders** tab to [view the generated leaderboard](/weave/guides/core-types/leaderboards).

## Use coding agents

You can connect coding agents to Serverless Inference through their OpenAI-compatible providers. The following configurations were tested with `zai-org/GLM-5.3-Flash`: Continue CLI `1.5.47`, Aider `0.86.2`, Zed `1.20.2`, Pi `0.86.1`, Qwen Code `0.24.3`, and OpenClaude `0.30.0`.

Complete the [account prerequisites](/inference/prerequisites#set-up-your-wb-account-and-project) and set the `WANDB_API_KEY` environment variable to your W&B API key. Check the [model catalog](https://wandb.ai/inference) for availability and pricing. These examples cap response length for small edits. The caps aren't the model's maximum output length.

<Tabs>
  <Tab title="Continue CLI">
    With Node.js 20 or later installed, install the tested [Continue CLI](https://docs.continue.dev/cli/quickstart) version:

    ```bash
    npm install -g @continuedev/cli@1.5.47
    ```

    Save the following configuration as `coreweave.yaml`. Continue resolves the secret from the `WANDB_API_KEY` environment variable. `useResponsesApi: false` selects Chat Completions, and `tool_use` enables agent tools.

    ```yaml
    name: Serverless Inference
    version: 1.0.0
    schema: v1
    models:
      - name: GLM 5.3 Flash
        provider: openai
        model: zai-org/GLM-5.3-Flash
        apiBase: https://api.inference.wandb.ai/v1
        apiKey: ${{ secrets.WANDB_API_KEY }}
        roles: [chat, edit]
        capabilities: [tool_use]
        useResponsesApi: false
        defaultCompletionOptions:
          contextLength: 131072
          maxTokens: 2048
    ```

    Start Continue with this configuration:

    ```bash
    cn --config ./coreweave.yaml
    ```

    This example uses a 131,072-token client context budget, below the model catalog's 1,048,576-token context window. It was validated with the CLI's file-read and file-edit tools. Editor extensions, autocomplete, and embeddings require separate configuration. For more options, see [Continue configuration](https://docs.continue.dev/cli/configuration).

## Configure bolt.diy

[bolt.diy](https://github.com/stackblitz-labs/bolt.diy/tree/v1.0.0#running-the-application) supports Serverless Inference through its **OpenAILike** provider. This setup was tested with bolt.diy `1.0.0` and `zai-org/GLM-5.3-Flash` in the browser's WebContainer runtime.

Follow the bolt.diy installation instructions, then set your W&B API key in `WANDB_API_KEY`. From your local bolt.diy directory, configure the endpoint and start the app:

```bash
export OPENAI_LIKE_API_BASE_URL="https://api.inference.wandb.ai/v1"
export OPENAI_LIKE_API_KEY="$WANDB_API_KEY"
pnpm run dev
```

In the app, select **OpenAILike** and the exact model ID `zai-org/GLM-5.3-Flash`. The provider discovers model IDs from `/models`, so this setup doesn't require a custom model row. In version `1.0.0`, OpenAILike assigns an 8,000-token output allowance to discovered models. This client allowance isn't the model's context window.

If a response appears as text but no file is created, check the artifact format. bolt.diy expects an outer `boltArtifact` element with `id` and `title`, containing a `boltAction` with `type="file"` and `filePath`. Ask the model to use those exact elements, include the complete file content, and close both tags. An `artifact` element with separate `type`, `path`, and `content` elements doesn't trigger a file action.

Verify the resulting file in the workbench after generation. A small live file-edit test preserved the expected content and trailing newline after explicit artifact-format guidance. This result doesn't establish consistent first-response compliance across models or larger tasks.

## Configure Tabby chat

[Tabby](https://tabby.tabbyml.com/docs/quick-start/installation/docker/) supports Serverless Inference as an OpenAI-compatible chat backend. This configuration was tested with the chat API in Tabby `0.32.0`.

On an existing Tabby server, merge the following section into `~/.tabby/config.toml`, or `config.toml` in your configured `TABBY_ROOT` directory. Replace `[YOUR-API-KEY]` with your W&B API key. The `api_key` field accepts a literal value and doesn't expand shell environment variables.

```toml
[model.chat.http]
kind = "openai/chat"
model_name = "zai-org/GLM-5.3-Flash"
supported_models = ["zai-org/GLM-5.3-Flash"]
api_endpoint = "https://api.inference.wandb.ai/v1"
api_key = "[YOUR-API-KEY]"
```

Keep your existing completion and embedding model configuration. Tabby `0.32.0` initializes an embedding backend at startup, even when you only use chat. This chat configuration doesn't provide code completion or embeddings.

Remove any `--chat-model` argument from your server startup command because it overrides the chat configuration. Restart the server to load your changes. Omit `/chat/completions` from `api_endpoint` because Tabby appends it. Validation covered authentication and streamed chat responses through the server API. Editor interfaces, retrieval, and file edits weren't tested. For backend options, see [Tabby's OpenAI HTTP model documentation](https://tabby.tabbyml.com/docs/references/models-http-api/openai/).
