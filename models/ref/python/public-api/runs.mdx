## <Badge color="yellow" size="lg" shape="rounded">Class</Badge> wandb.apis.public.Runs



A lazy iterator of `Run` objects associated with a project and optional filter.

Runs are retrieved in pages from the W&B server as needed.

This is generally used indirectly using the `Api.runs` namespace.



```python
(service_api: 'ServiceApi',
entity: 'str',
project: 'str',
filters: 'dict[str, Any] | None' = None,
order: 'str' = '+created_at',
per_page: 'int' = 50,
include_sweeps: 'bool' = False,
lazy: 'bool' = True,
api_key: 'str | None' = None)
```

## Args

<ResponseField name="service_api" type="ServiceApi">
The service API to use for requests.
</ResponseField>

<ResponseField name="entity" type="str">
The entity (username or team) that owns the project.
</ResponseField>

<ResponseField name="project" type="str">
The name of the project to fetch runs from.
</ResponseField>

<ResponseField name="filters" type="dict[str, Any] | None">
Filters to apply to the runs query.
</ResponseField>

<ResponseField name="order" type="str">
Order can be `created_at`, `heartbeat_at`, `config.*.value`, or `summary_metrics.*`. If you prepend order with a + order is ascending (default). If you prepend order with a - order is descending. The default order is run.created_at from oldest to newest.
</ResponseField>

<ResponseField name="per_page" type="int">
The number of runs to fetch per request (default is 50).
</ResponseField>

<ResponseField name="include_sweeps" type="bool">
Whether to include sweep information in the runs. Defaults to True.
</ResponseField>

<ResponseField name="lazy" type="bool">
Whether to defer loading heavy fields (config, summaryMetrics, systemMetrics) until they are accessed. Defaults to True.
</ResponseField>

<ResponseField name="api_key" type="str | None">
No value provided.
</ResponseField>
