When you run a cell, its output appears below it. By default, the notebook automatically runs cells that depend on variables defined by that cell so that they use the latest values.

If you delete a cell, the global variables defined in that cell are also deleted.

Notebooks don't track in-place mutations to objects. For example, if one cell adds a column to a DataFrame defined in another cell, cells that reference the DataFrame don't automatically rerun. To keep the notebook state consistent, mutate an object in the cell that defines it or assign the updated value to a new variable. For more information, see [How marimo runs cells](https://docs.marimo.io/guides/reactivity/#how-marimo-runs-cells).

Define each global variable in only one cell. For temporary variables, [prefix the name with a single underscore](https://docs.marimo.io/guides/reactivity/#creating-local-variables) to make it local to that cell. You can also [define temporary variables within a function](https://docs.marimo.io/guides/reactivity/#encapsulating-code-in-functions).

## Understand stale and blocked cells

A cell is *stale* if it hasn't run with its latest code and inputs. A cell that has never run is also stale. After a cell runs with its current code and inputs, it is no longer stale.

A cell becomes stale when:

- You edit the cell's code.
- An ancestor cell runs while the notebook uses lazy execution. In this mode, the notebook marks dependent cells as stale instead of automatically running them.
- A Python module used by the cell changes while lazy module autoreloading is enabled.

Run a stale cell to update its output. If the cell has stale ancestors, the notebook runs those cells first. You can also run all stale cells at once.

<Info>
In-place mutations don't mark dependent cells as stale because notebooks don't track mutations to objects.
</Info>

## Navigate cell relationships with the minimap

Use the [Dependencies panel](https://docs.marimo.io/guides/editor_features/dataflow/#dependencies-panel) to understand relationships between cells.

1. From the sidebar, select **Explore dependencies** (<Icon icon="sitemap" iconType="solid"/>). 
2. Select **MINIMAP**.

## View the dependency graph

Use the [Graph view](https://docs.marimo.io/guides/editor_features/dataflow/#graph-view) to visualize dependencies between cells as a directed acyclic graph (DAG).

1. From the sidebar, select **Explore dependencies** (<Icon icon="sitemap" iconType="solid"/>). 
2. Select **GRAPH**.

You can zoom in and out, drag, and rearrange nodes to better understand the relationships between cells.
