<div id="class-wandbartifact">
  ## <Badge color="yellow" size="lg" shape="rounded">Classe</Badge> wandb.Artifact
</div>

Composant flexible et léger pour la gestion des versions des jeux de données et des modèles.

Créez un W&amp;B Artifact vide. Remplissez le contenu d’un Artifact avec des méthodes qui
commencent par `add`. Une fois que l’Artifact contient tous les fichiers souhaités, vous pouvez appeler
`run.log_artifact()` pour le journaliser.

```python
name: 'str',
type: 'str',
description: 'str | None' = None,
metadata: 'dict[str, Any] | None' = None,
incremental: 'bool' = False,
use_as: 'str | None' = None,
storage_region: 'str | None' = None,
digest_algorithm: "Literal['MD5', 'XXH128']" = 'MD5'
```

  ## Arguments
</div>

<ResponseField name="name" type="str">
  Un nom facile à lire pour l&#39;artifact. Utilisez ce nom pour identifier un artifact spécifique dans l&#39;interface de l&#39;application W&amp;B ou par programmation. Vous pouvez référencer un artifact de manière interactive avec l&#39;API publique `use_artifact`. Un nom peut contenir des lettres, des chiffres, des traits de soulignement, des traits d&#39;union et des points. Le nom doit être unique dans un projet.
</ResponseField>

<ResponseField name="type" type="str">
  Le type de l&#39;artifact. Utilisez le type d&#39;un artifact pour organiser et différencier les Artifacts. Vous pouvez utiliser n&#39;importe quelle chaîne contenant des lettres, des chiffres, des traits de soulignement, des traits d&#39;union et des points. Les types courants incluent `dataset` ou `model`. Incluez `model` dans votre chaîne de type si vous souhaitez lier l&#39;artifact au registre de modèles W&amp;B. Notez que certains types sont réservés à un usage interne et ne peuvent pas être définis par les utilisateurs. Ces types incluent `job` et les types qui commencent par `wandb-`.
</ResponseField>

<ResponseField name="description" type="str | None">
  Une description de l&#39;artifact. Pour les Artifacts de type Model ou Dataset, ajoutez la documentation de votre carte de modèle ou de jeu de données standardisée pour l&#39;équipe. Consultez la description d&#39;un artifact par programmation avec l&#39;attribut `Artifact.description` ou dans l&#39;interface de l&#39;application W&amp;B. W&amp;B affiche la description au format markdown dans l&#39;application W&amp;B.

<ResponseField name="metadata" type="dict[str, Any] | None">

</ResponseField>

<ResponseField name="incremental" type="bool">

<ResponseField name="use_as" type="str | None">
  Obsolète.
</ResponseField>

<ResponseField name="storage_region" type="str | None">

<div id="method-artifactadd_reference">
  ### <Badge color="blue" size="lg" shape="rounded">méthode</Badge> Artifact.add_reference()
</div>

```python
self,
uri: 'ArtifactManifestEntry | str',
name: 'StrPath | None' = None,
checksum: 'bool' = True,
max_objects: 'int | None' = None
```

Ajoutez à l&#39;artifact une référence désignée par un URI.

Contrairement aux fichiers ou répertoires que vous ajoutez à un artifact, les références ne sont pas téléversées vers W&amp;B. Pour plus d&#39;informations, voir [Suivre des fichiers externes](https://docs.wandb.ai/models/artifacts/track-external-files).

Par défaut, les schémas suivants sont pris en charge :

* http(s) : la taille et le digest du fichier sont déduites des en-têtes de réponse `Content-Length` et `ETag` renvoyés par le serveur.
* s3 : la somme de contrôle et la taille sont récupérées à partir des métadonnées de l&#39;objet. Si la gestion des versions du bucket est activée, l&#39;ID de version est également suivi.
* gs : la somme de contrôle et la taille sont récupérées à partir des métadonnées de l&#39;objet. Si la gestion des versions du bucket est activée, l&#39;ID de version est également suivi.
* https, domaine correspondant à `*.blob.core.windows.net`
* Azure : la somme de contrôle et la taille sont récupérées à partir des métadonnées du blob. Si la gestion des versions du compte de stockage est activée, l&#39;ID de version est également suivi.
* file : la somme de contrôle et la taille sont récupérées à partir du système de fichiers. Ce schéma est utile si vous avez un partage NFS ou un autre volume monté en externe contenant des fichiers que vous souhaitez suivre sans nécessairement les téléverser.

Pour tout autre schéma, le digest est simplement un hachage de l&#39;URI et la taille reste vide.

<div id="arguments-4">
  ##### Arguments
</div>

<ResponseField name="uri" type="ArtifactManifestEntry | str">
  le chemin URI de la référence à ajouter. Le chemin URI peut être un objet renvoyé par `Artifact.get_entry` pour stocker une référence vers l&#39;entrée d&#39;un autre artifact.
</ResponseField>

<ResponseField name="name" type="StrPath | None">
  le chemin au sein de l&#39;artifact où placer le contenu de cette référence.
</ResponseField>

<ResponseField name="checksum" type="bool">
  indique s&#39;il faut calculer ou non une somme de contrôle pour la ou les ressources situées à l&#39;URI de référence. Le calcul de la somme de contrôle est fortement recommandé, car il permet une validation automatique de l&#39;intégrité. Le désactiver accélère la création de l&#39;artifact, mais les répertoires de référence ne seront pas parcourus, de sorte que les objets du répertoire ne seront pas enregistrés dans l&#39;artifact. Nous vous recommandons de définir `checksum=False` lors de l&#39;ajout d&#39;objets de référence ; dans ce cas, une nouvelle version ne sera créée que si l&#39;URI de référence change.
</ResponseField>

<ResponseField name="max_objects" type="int | None">
  le nombre maximal d&#39;objets à prendre en compte lors de l&#39;ajout d&#39;une référence pointant vers un répertoire ou un préfixe de stockage de bucket. Par défaut, le nombre maximal d&#39;objets autorisé pour Amazon S3, GCS, Azure et les fichiers locaux est de 10,000,000. Les autres schémas d&#39;URI n&#39;ont pas de limite.
</ResponseField>

<div id="raises-4">
  ##### Exceptions levées
</div>

* `ArtifactFinalizedError`: Vous ne pouvez pas modifier la version actuelle de l&#39;artifact, car elle est finalisée. Enregistrez plutôt une nouvelle version de l&#39;artifact.

<div id="method-artifactdelete">
  ### <Badge color="blue" size="lg" shape="rounded">méthode</Badge> Artifact.delete()
</div>

```python
self,
delete_aliases: 'bool' = False
```

Supprime un artifact et ses fichiers.

Si cette méthode est appelée sur un artifact lié, seul le lien est supprimé, et l’artifact source n’est pas affecté.

Utilisez `Artifact.unlink()` au lieu de `Artifact.delete()` pour supprimer le lien entre un artifact source et une collection.

<div id="arguments-6">
  ##### Arguments
</div>

<ResponseField name="delete_aliases" type="bool">
  Si défini sur `True`, supprime tous les alias associés à l’artifact. Si `False`, lève une exception si l’artifact possède déjà des alias. Ce paramètre est ignoré si l’artifact est récupéré depuis une collection à laquelle il est lié.
</ResponseField>

<div id="raises-6">
  ##### Exceptions levées
</div>

* `ArtifactNotLoggedError`: Si l’artifact n’est pas enregistré.

<div id="method-artifactdownload">
  ### <Badge color="blue" size="lg" shape="rounded">méthode</Badge> Artifact.download()
</div>

```python
self,
root: 'StrPath | None' = None,
allow_missing_references: 'bool' = False,
skip_cache: 'bool | None' = None,
path_prefix: 'StrPath | None' = None,
multipart: 'bool | None' = None
```

Télécharge le contenu de l&#39;artifact dans le répertoire racine spécifié.

Les fichiers existants dans `root` ne sont pas modifiés. Supprimez explicitement `root`
avant d&#39;appeler `download` si vous voulez que son contenu corresponde exactement à celui de l&#39;artifact.

<div id="arguments-7">
  ##### Arguments
</div>

<ResponseField name="root" type="StrPath | None">
  Le répertoire dans lequel W&amp;B stocke les fichiers de l&#39;artifact.
</ResponseField>

<ResponseField name="allow_missing_references" type="bool">
  Si défini sur `True`, tous les chemins de référence invalides seront ignorés lors du téléchargement des fichiers référencés.
</ResponseField>

<ResponseField name="skip_cache" type="bool | None">
  Si défini sur `True`, le cache de l&#39;artifact sera ignoré lors du téléchargement, et W&amp;B téléchargera chaque fichier dans le répertoire racine par défaut ou dans le répertoire de téléchargement spécifié.
</ResponseField>

<ResponseField name="path_prefix" type="StrPath | None">
  Si spécifié, seuls les fichiers dont le chemin commence par le préfixe indiqué seront téléchargés. Utilise le format Unix (barres obliques `/`).
</ResponseField>

<ResponseField name="multipart" type="bool | None">
  Si défini sur `None` (par défaut), l&#39;artifact sera téléchargé en parallèle à l&#39;aide d&#39;un téléchargement multipart si la taille d&#39;un fichier individuel dépasse 2 Go. Si défini sur `True` ou `False`, l&#39;artifact sera téléchargé en parallèle ou en série, quelle que soit la taille du fichier.
</ResponseField>

<div id="raises-7">
  ##### Exceptions levées
</div>
