<div id="attributes">
  ## Attributs
</div>

* `tags` (`[str]`) : une liste de tags associés au run
* `url` (`str`) : l’URL de ce run
* `id` (`str`) : identifiant unique du run (huit caractères par défaut)
* `name` (`str`) : le nom du run
* `state` (`str`) : l’une des valeurs suivantes : running, finished, crashed, killed, preempting, preempted
* `config` (`dict`) : un dictionnaire d’hyperparamètres associés au run
* `created_at` (`str`) : horodatage ISO au démarrage du run
* `system_metrics` (`dict`) : les dernières métriques système enregistrées pour le run
* `summary` (`dict`) : propriété mutable de type dictionnaire qui contient la synthèse actuelle. Tout appel à `update` persistera les modifications.
* `project` (`str`) : le projet associé au run
* `entity` (`str`) : le nom de l’entité associée au run
* `project_internal_id` (`int`) : l’ID interne du projet
* `user` (`str`) : le nom de l’utilisateur qui a créé le run
* `path` (`str`) : identifiant unique [entity]/[project]/[run&#95;id]
* `notes` (`str`) : notes sur le run
* `read_only` (`boolean`) : indique si le run est modifiable
* `history_keys` (`str`) : clés des métriques de l’historique enregistrées avec `wandb.Run.log({"key": "value"})`
* `metadata` (`str`) : métadonnées sur le run issues de wandb-metadata.json

<div id="method-runconsole_logs">
  ### <Badge color="blue" size="lg" shape="rounded">méthode</Badge> Run.console_logs()
</div>

```python
self, *,
per_page: 'int' = 1000,
last: 'int | None' = None
```

Renvoie la sortie de console capturée du run.

Pendant l&#39;exécution d&#39;un run, W&amp;B capture ce que son processus écrit sur
stdout et stderr et l&#39;enregistre dans le journal de console du run — le
même journal affiché dans l&#39;onglet &quot;Logs&quot; de la page du run dans l&#39;application W&amp;B.
Cette méthode relit ce journal, aussi bien pour les runs terminés que pour ceux encore
en cours d&#39;exécution.

<div id="arguments-2">
  ##### Arguments
</div>

<ResponseField name="per_page" type="int">
  Nombre de lignes à récupérer par requête lors de la lecture du journal depuis le début. Ignoré lorsque `last` est spécifié.
</ResponseField>

<ResponseField name="last" type="int | None">
  Si défini, récupère uniquement les N dernières lignes du journal en une seule requête — utile pour vérifier un run en cours ou diagnostiquer un plantage. Le backend limite le nombre de lignes renvoyées par requête ; une portion finale plus importante est donc tronquée aux lignes les plus récentes.
</ResponseField>

<div id="raises">
  ##### Exceptions levées
</div>

* `CommError` : si une requête échoue lors de l’itération. La lecture du journal depuis le début nécessite le serveur W&amp;B 0.77 ou une version ultérieure ; sur les serveurs plus anciens, lisez plutôt les N dernières lignes.

<div id="examples">
  ##### Exemples
</div>

```python
import wandb

run = wandb.Api().run("entity/project/run_id")

# Lire l'intégralité du journal, de la ligne la plus ancienne à la plus récente.
for line in run.console_logs():
    print(line.content)

# Lire uniquement les 100 dernières lignes.
for line in run.console_logs(last=100):
    print(line.timestamp, line.content)
```

<div id="method-runcreate">
  ### <Badge color="blue" size="lg" shape="rounded">méthode</Badge> Run.create()
</div>

```python
api: 'public.Api',
run_id: 'str | None' = None,
project: 'str | None' = None,
entity: 'str | None' = None,
state: "Literal['running', 'pending']" = 'running'
```

Crée un run pour le projet donné.

Dans la plupart des cas, utilisez `wandb.init()`. `wandb.init()` offre un mécanisme plus robuste
pour créer et mettre à jour des runs. `wandb.apis.public.Run.create`
est destiné à des cas spécifiques, comme la création de runs à l’état
&quot;pending&quot; pour des jobs qui peuvent ne pas être planifiables
(par exemple, dans un cluster Kubernetes avec un nombre insuffisant de GPU ou une forte
contention). Ces runs en attente peuvent ensuite être repris et suivis par W&amp;B.

Les runs créés avec cette méthode ont des capacités limitées. L’appel à
`update()` sur un run créé de cette manière peut ne pas fonctionner comme prévu.

<div id="arguments-3">
  ##### Arguments
</div>

<ResponseField name="api" type="public.Api">
  L’instance de l’API W&amp;B.
</ResponseField>

<ResponseField name="run_id" type="str | None">
  ID du run facultatif. S’il n’est pas fourni, un ID aléatoire est généré.
</ResponseField>

<ResponseField name="project" type="str | None">
  Nom du projet facultatif. Par défaut, il s’agit du projet défini dans les paramètres de l’API ou de « uncategorized ».
</ResponseField>

<ResponseField name="entity" type="str | None">
  Nom de l’entité facultatif (utilisateur ou équipe).
</ResponseField>

<ResponseField name="state" type="Literal['running', 'pending']">
  État initial du run. Utilisez « pending » pour les runs qui seront repris ultérieurement, ou « running » pour une exécution immédiate.
</ResponseField>

<div id="examples-2">
  ##### Exemples
</div>

Création d’un run en attente pour une exécution ultérieure

```python
import wandb

api = wandb.Api()

run_name = "my-pending-run"

run = Run.create(
    api=api,
    project="project",
    entity="entity",
    state="pending",
    run_id=run_name,
)
```

<div id="method-runstop">
  ### <Badge color="blue" size="lg" shape="rounded">méthode</Badge> Run.stop()
</div>

```python
self
```

Demande l’arrêt propre de ce run.

Cette méthode définit l’indicateur d’arrêt de ce run sur le backend W&amp;B, c’est le même signal
que celui envoyé par le bouton &quot;Stop run&quot; dans l’interface de l’application W&amp;B. Le processus qui exécute
le run détecte cet indicateur lors de son heartbeat habituel, puis arrête
le run proprement. Cette méthode peut donc être utilisée en toute sécurité pour arrêter des runs distants
(par exemple, des runs exécutés sur des pods Kubernetes).

L’arrêt est asynchrone : cette méthode renvoie dès que le backend a
activé l’indicateur d’arrêt du run, et non lorsque le run est effectivement terminé. La rappeler, ou l’appeler
sur un run qui n’est plus en cours d’exécution, n’a aucun effet.

<div id="raises-4">
  ##### Exceptions levées
</div>

* `wandb.Error`: Si la requête échoue.

<div id="examples-4">
  ##### Exemples
</div>

```python
import wandb

run = wandb.Api().run("entity/project/run_id")
run.stop()
```

<div id="method-runupdate_state">
  ### <Badge color="blue" size="lg" shape="rounded">méthode</Badge> Run.update_state()
</div>

```python
self,
state: 'str'
```

Met à jour l’état d’un run.

Transitions prises en charge :

* vers `pending` depuis `running`, `failed`, `crashed` ou `preempted`
  (par ex. pour remettre en file d’attente un run terminé ou en cours)
  * vers `failed` depuis `pending` ou `running`
    (par ex. pour marquer un run préempté ou perdu comme failed)

L’état des runs de balayage ne peut pas être mis à jour.

Voir `Run.state` pour la liste des états de run possibles.

<div id="arguments-15">
  ##### Arguments
</div>

<ResponseField name="state" type="str">
  L’état cible du run. L’une des valeurs `"pending"` ou `"failed"`.
</ResponseField>

<div id="raises-5">
  ##### Exceptions levées
</div>

* `wandb.Error`: Si la transition d’état demandée n’est pas autorisée ou si le serveur ne prend pas en charge cette opération.


Récupère les artifacts explicitement utilisés par ce run.

Récupère uniquement les artifacts d’entrée qui ont été explicitement déclarés comme utilisés
lors du run, généralement via `run.use_artifact()`. Renvoie un résultat paginé
qui peut être parcouru ou regroupé dans une seule liste.

<div id="arguments-18">
  ##### Arguments
</div>

<ResponseField name="per_page" type="int">
  Nombre d&#39;artifacts à récupérer par requête API.
</ResponseField>

<div id="examples-5">
  ##### Exemples
</div>

```python
import wandb

run = wandb.init(project="artifact-example")
run.use_artifact("test_artifact:latest")
run.finish()

api = wandb.Api()
finished_run = api.run(f"{run.entity}/{run.project}/{run.id}")
for used_artifact in finished_run.used_artifacts():
    print(used_artifact.name)
test_artifact
```
