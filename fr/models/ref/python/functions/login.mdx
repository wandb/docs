<div id="function-wandblogin">
  ## <Badge color="blue" size="lg" shape="rounded">fonction</Badge> wandb.login()
</div>

Connectez-vous à W&amp;B.

En général, vous n&#39;avez pas besoin d&#39;utiliser ceci, car la plupart des méthodes W&amp;B qui nécessitent une authentification peuvent se connecter implicitement. Il s&#39;agit de l&#39;équivalent programmatique de la commande CLI `wandb login`.

Cette opération met à jour les identifiants globaux de la session (ce qui affecte toute utilisation de wandb dans le processus Python en cours après cet appel) et, éventuellement, le fichier .netrc.

Si un fichier de jeton d&#39;identité est configuré, par exemple via la
variable d&#39;environnement WANDB&#95;IDENTITY&#95;TOKEN&#95;FILE, il est utilisé pour la
session (identité fédérée) et aucune clé API n&#39;est lue ni enregistrée.

Sinon, si une clé API explicite est fournie, elle est utilisée et écrite dans le fichier système .netrc. Si aucune clé n&#39;est fournie, mais que la session est déjà authentifiée, la clé de session est utilisée pour la vérification (si verify vaut True) et le fichier .netrc n&#39;est pas mis à jour.

Si aucun des cas ci-dessus ne s&#39;applique, cette opération récupère la clé API depuis la première des sources suivantes :

* La variable d&#39;environnement WANDB&#95;API&#95;KEY
* Le paramètre api&#95;key dans un fichier de paramètres système ou de Workspace
* Le fichier .netrc (soit ~/.netrc, ~/&#95;netrc ou le chemin spécifié par la
  variable d&#39;environnement NETRC)
* Une invite interactive (si disponible)

```python
key: 'str | None' = None,
relogin: 'bool | None' = None,
host: 'str | None' = None,
force: 'bool | None' = None,
timeout: 'int | None' = None,
verify: 'bool' = True,
referrer: 'str | None' = None,
anonymous: 'DoNotSet' = DoNotSet
```

<div id="args">
  ## Arguments
</div>

<ResponseField name="key" type="str | None">
  La clé API à utiliser.
</ResponseField>

<ResponseField name="relogin" type="bool | None">
  Si la valeur est true, récupère la clé API via une invite interactive, sans lire .netrc, les variables d’environnement, etc.
</ResponseField>

<ResponseField name="host" type="str | None">
  L’URL du serveur W&amp;B auquel se connecter.
</ResponseField>

<ResponseField name="force" type="bool | None">
  Si la valeur est true, empêche de sélectionner le mode hors ligne dans l’invite interactive.
</ResponseField>

<ResponseField name="timeout" type="int | None">
  Nombre de secondes pendant lesquelles attendre une saisie de l’utilisateur dans l’invite interactive. Peut servir de mécanisme de sécurité si une invite interactive s’affiche par erreur dans un environnement non interactif.
</ResponseField>

<ResponseField name="verify" type="bool">
  Vérifie les identifiants d’authentification auprès du serveur W&amp;B et lève une AuthenticationError en cas d’échec. Fonctionne avec les clés API comme avec les jetons d’identité.
</ResponseField>

<ResponseField name="referrer" type="str | None">
  Le référent à utiliser dans la requête de connexion par URL à des fins d’analyse.
</ResponseField>

<ResponseField name="anonymous" type="DoNotSet">
  Aucune description fournie.
</ResponseField>

<div id="returns">
  ## Renvoie
</div>

`bool`: Si `key` est configurée.

<div id="raises">
  ## Exceptions levées
</div>

* `AuthenticationError`: Si les identifiants d’authentification échouent à la vérification auprès du serveur.
* `UsageError`: Si `api_key` ne peut pas être configurée et qu&#39;aucun tty n&#39;est disponible.
