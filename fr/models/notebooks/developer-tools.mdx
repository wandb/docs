## Ouvrir le panneau de développement {#open-the-developer-panel}

Utilisez l&#39;une des méthodes suivantes :

* Dans le pied de page du notebook, sélectionnez **panneau de développement**.
* Appuyez sur **Command+J** sous macOS, ou **Ctrl+J** sous Windows ou Linux. Ce raccourci ouvre ou ferme le panneau de développement.

## Inspecter les erreurs et les avertissements {#inspect-errors-and-warnings}

L&#39;onglet **Errors** affiche les erreurs et les avertissements de l&#39;ensemble du notebook, y compris les exceptions Python, les erreurs de syntaxe, les cycles, les dépendances réactives non valides et les variables définies dans plusieurs cellules.

## Utiliser le scratchpad {#use-the-scratchpad}

Utilisez l&#39;onglet **Scratchpad** pour exécuter du code Python temporaire sans l&#39;ajouter au graphe réactif du notebook. Le scratchpad peut accéder aux variables définies dans les cellules de notebook.

Contrairement aux cellules de notebook, le scratchpad n&#39;impose pas l&#39;unicité des noms de variables globales. Le code et les variables définis dans le scratchpad ne sont pas enregistrés : copiez dans une cellule de notebook tout code que vous souhaitez conserver.

Pour exécuter le code du scratchpad, appuyez sur **Command+Entrée** sous macOS ou sur **Control+Entrée** sous Windows ou Linux. Vous pouvez également sélectionner **Run** (<Icon icon="circle-play" iconType="solid" />).

La sortie du scratchpad s&#39;affiche à droite du code.

## Inspecter les traces d&#39;exécution {#inspect-execution-traces}

Utilisez l&#39;onglet **Tracing** pour inspecter l&#39;ordre et la durée d&#39;exécution des cellules. Les traces vous aident à identifier les cellules lentes ou en échec et à déterminer quelles cellules ont été exécutées lors d&#39;un event d&#39;exécution réactive.

Chaque en-tête **Run** regroupe les cellules exécutées au cours d&#39;un même event d&#39;exécution. Les barres horizontales indiquent à quel moment chaque cellule a été exécutée et permettent de comparer sa durée à celle des autres cellules de l&#39;event. Chaque entrée comprend un lien vers la cellule, un aperçu du code, la durée et une icône de statut. Cette icône indique si l&#39;exécution a réussi, échoué ou été interrompue.

Les exécutions courtes peuvent afficher `0 ms`, car les durées sont arrondies. Survolez une entrée de trace pour afficher les heures de début et de fin précises. Sélectionnez un lien de cellule pour ouvrir la cellule de notebook correspondante.

Sélectionnez **Clear** pour supprimer l&#39;historique des traces affiché. Effacer l&#39;historique ne supprime ni les cellules du notebook ni les variables.

Activez **Inline chart** pour afficher le temps d&#39;exécution à proximité des cellules de notebook correspondantes.

Les deux cellules se sont exécutées avec succès. La trace indique une durée de 14 ms pour `cell-4` et de `0 ms` pour `cell-5`. Une info-bulle affiche les heures de début et de fin précises pour `cell-5`.

## Afficher les journaux {#view-logs}

Utilisez l&#39;onglet **Logs** pour consulter la sortie standard (`stdout`) et la sortie d&#39;erreur standard (`stderr`) des cellules de notebook et du scratchpad. Les journaux vous permettent d&#39;analyser les échecs d&#39;exécution qui ne génèrent pas de message d&#39;erreur explicite en ligne.

L&#39;image suivante montre la sortie `"Do you have a cat?"` journalisée à `[5:42:51 PM]` par la cellule de notebook correspondante.

## Utiliser le terminal {#use-the-terminal}

Utilisez l&#39;onglet **Terminal** pour ouvrir un shell dans le même environnement sandbox que le runtime du notebook. Depuis le terminal, vous pouvez inspecter les fichiers, exécuter des outils en ligne de commande, gérer les paquets et lancer des scripts. Les modifications effectuées dans le terminal s&#39;appliquent au même Workspace que le notebook.
