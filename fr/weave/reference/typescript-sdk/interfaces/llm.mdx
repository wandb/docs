Un appel LLM. Émet un span `chat` avec des attributs `gen_ai.*`.

Créé par `weave.startLLM()` (ou `turn.startLLM()`) et terminé par
`end()`. Un seul LLM peut être actif à la fois dans un contexte asynchrone ; imbriquez
les appels d&#39;outil ou de sous-agent en dessous via `startTool` / `startSubagent`.

Renseignez directement `inputMessages` / `outputMessages` / `usage` / `reasoning`,
ou utilisez les fonctions utilitaires (`output`, `think`, `attachMedia`, `record`).

Toutes les données enregistrées font l’objet d’un vidage dans le span lors de `end()`.

## Exemples {#examples}

```ts twoslash
// @noErrors
const llm = weave.startLLM({model: 'gpt-4o-mini', providerName: 'openai'});

try {
  llm.inputMessages = [{role: 'user', content: prompt}];
  const resp = await openai.chat.completions.create({...});
  llm.output(resp.choices[0].message.content ?? '');
  llm.record({usage: {inputTokens: resp.usage?.prompt_tokens}});
} finally {
  llm.end();
}
```

```ts twoslash
// @noErrors
const llm = weave.startLLM({
  model: 'gpt-4o-mini',
  providerName: 'openai',
  systemInstructions: ['You are a helpful weather bot.'],
  startTime: new Date('2026-05-29T10:00:00.000Z'),
});

try {
  // ... appelez le LLM, renseignez llm.outputMessages / usage ...
} finally {
  llm.end();
}
```

## Propriétés {#properties}

### inputMessages {#inputmessages}

> **inputMessages** : [`Message`](./message)[] = `[]`

Messages d’entrée envoyés au modèle. Font l’objet d’un vidage dans `gen_ai.input.messages` lors de
`end()`.

***

### modèle {#model}

> `readonly` **modèle**: `string`

***

### outputMessages {#outputmessages}

> **outputMessages** : [`Message`](./message)[] = `[]`

Messages de l’assistant renvoyés par le modèle. Font l’objet d’un vidage dans
`gen_ai.output.messages` lors de l’appel à `end()`.

***

### nom du fournisseur {#providername}

> `readonly` **nom du fournisseur** : `string`

***

### raisonnement {#reasoning}

> `facultatif` **raisonnement** : [`Reasoning`](./reasoning)

Contenu de chaîne de pensée. Intégré au dernier message de l’assistant sous forme de
ReasoningPart lors de la sérialisation.

***

### utilisation {#usage}

> **utilisation** : [`Usage`](./usage) = `{}`

Nombre de jetons et statistiques du cache. Font l’objet d’un vidage dans `gen_ai.usage.*` lors de l’appel à `end()`.

## Méthodes {#methods}

### ~~addEvent()~~ {#addevent}

<Warning>
  **Obsolète.** Enregistrez plutôt ces données avec [setAttributes](#setattributes).
  OpenTelemetry abandonne progressivement l’API d’événements de span (`Span.addEvent`). Cette
  méthode fonctionne toujours et les données d’événements de span existantes restent valides.
  Voir [https://opentelemetry.io/blog/2026/deprecating-span-events/](https://opentelemetry.io/blog/2026/deprecating-span-events/)
</Warning>

> **addEvent**(`name`, `attributes?`, `startTime?`): `this`

Ajoute un événement nommé au span. Utile pour marquer des moments qui ne correspondent pas à des spans, tels que
la compaction du contexte, la détection de boucles d’outils ou le déclenchement de garde-fous. Émet un avertissement et
ne fait rien après `end()`. Reproduit le comportement de `Span.addEvent` d’OTel.

#### Paramètres {#parameters}

<ParamField path="name" type="string" required />

<ParamField path="attributes" type="Attributes" />

<ParamField path="startTime" type="TimeInput" />

#### Renvoie {#returns}

`this`

#### Exemple {#example}

```ts twoslash
// @noErrors
span.addEvent('context_compacted', {removedMessages: 12});
```

### attachMedia() {#attachmedia}

> **attachMedia**(`opts`) : `this`

Prépare une pièce jointe multimédia pour l’appel LLM. Choisissez exactement l’un des éléments suivants :
`content` (octets base64 intégrés), `uri` (référence URI) ou `fileId`
(ID de fichier déjà téléversé). La pièce jointe est ajoutée au dernier
message utilisateur d’`inputMessages` lors de l’appel à `end()`.

#### Paramètres {#parameters-2}

<ParamField path="opts" type="{…} | {…} | {…}" required>

  Type complet : `{ content: string; mimeType: string; modality: Modality; } | { modality: Modality; uri: string; } | { fileId: string; mimeType?: string; modality: Modality; }`
</ParamField>

#### Renvoie {#returns-2}

`this`

### think() {#think}

> **think**(`content`) : `this`

Définit ou complète le contenu de raisonnement/chaîne de pensée du modèle. Ce contenu est accumulé
dans `this.reasoning.content`. Lors de la sérialisation, il est intégré au dernier message de l’assistant
sous la forme d’un `ReasoningPart`, conformément au format transmis par le SDK Python.
