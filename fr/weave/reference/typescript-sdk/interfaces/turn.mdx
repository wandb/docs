Un appel d&#39;agent. Encapsule généralement le traitement nécessaire pour répondre à un
seul message utilisateur. Émet un span `invoke_agent` et sert de racine à la
trace de ce tour de conversation : il est toujours démarré sous `ROOT_CONTEXT`, afin de
n&#39;hériter jamais accidentellement d&#39;un parent provenant d&#39;une autre bibliothèque instrumentée avec OTel.

Créé par `weave.startTurn()` (ou `conversation.startTurn()`) et
terminé avec `end()`. Un seul tour de conversation peut être actif dans une chaîne asynchrone.
Les enfants (LLM, Tool, SubAgent) s&#39;y rattachent via les méthodes `startLLM`, `startTool`
et `startSubagent`.

## Exemples {#examples}

```ts twoslash
// @noErrors
const turn = weave.startTurn();

try {
  const llm = turn.startLLM({model: 'gpt-4o', providerName: 'openai'});
  // ...
  llm.end();
} finally {
  turn.end();
}
```

```ts twoslash
// @noErrors
const turn = weave.startTurn({
  model: 'gpt-4o',
  agentName: 'research-bot',
  agentId: 'research-bot-prod',
  agentDescription: 'Looks up facts on Wikipedia.',
  agentVersion: '1.4.2',
  userMessage: 'What is the weather in Tokyo?',
  systemInstructions: ['You are a helpful weather bot.'],
  startTime: new Date('2026-05-29T10:00:00.000Z'),
});

try {
  const llm = turn.startLLM({model: 'gpt-4o', providerName: 'openai'});
  // ...
  llm.end();
} finally {
  turn.end();
}
```

### ~~addEvent()~~ {#addevent}

<Warning>
  **Obsolète.** Enregistrez plutôt ces données via [setAttributes](#setattributes).
  OpenTelemetry abandonne progressivement l’API d’événements de span (`Span.addEvent`). Cette
  méthode fonctionne toujours et les données d’événements de span existantes restent valides.
  Voir [https://opentelemetry.io/blog/2026/deprecating-span-events/](https://opentelemetry.io/blog/2026/deprecating-span-events/)
</Warning>

> **addEvent**(`name`, `attributes?`, `startTime?`): `this`

Ajoute un événement nommé au span. Utile pour marquer des moments ne correspondant pas à des spans, tels que
la compaction du contexte, la détection de boucles d’outils ou le déclenchement de guardrails. Émet un avertissement et
ne fait rien après `end()`. Reproduit `Span.addEvent` d’OTel.

#### Paramètres {#parameters}

<ParamField path="name" type="string" required />

<ParamField path="attributes" type="Attributes" />

<ParamField path="startTime" type="TimeInput" />

#### Renvoie {#returns-3}

`this`

#### Exemple {#example}

```ts twoslash
// @noErrors
span.addEvent('context_compacted', {removedMessages: 12});
```

### end() {#end}

> **end**(`opts?`) : `void`

Lisez les valeurs actuelles des champs (afin de refléter les modifications apportées via `record()`
depuis `start`) et fermez le span. Cette opération est idempotente. Transmettez `error` pour le marquer
comme ayant échoué ; transmettez `endTime` pour antidater sa fermeture.

#### Paramètres {#parameters-2}

    <ParamField path="error" type="Error" />
  </Expandable>
</ParamField>

#### Renvoie {#returns-4}

`void`

### record() {#record}

> **record**(`opts`) : `this`

Définit en bloc n’importe quel sous-ensemble de champs modifiables. Remplace les valeurs existantes (sans les fusionner).
